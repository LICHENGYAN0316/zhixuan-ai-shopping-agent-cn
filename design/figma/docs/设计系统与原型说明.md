# 设计系统与交互原型说明

## 1. 视觉方向

视觉系统采用暖白画布、石墨黑主色、铜橙强调色和证据绿状态色。它不模仿任何电商平台品牌，而是突出“理性决策工具”的产品定位：正文克制、证据明确、取舍可见。

## 2. Variables 与 Styles

- 73 个 Variables，分为 Primitive colors、Semantic colors 和 Sizing 三组。
- 语义色覆盖 Canvas、Surface、Inverse、Accent、Success、Warning、Danger、Border、Text、Icon 与 Action。
- 尺寸变量覆盖 spacing、radius 和常用布局间距。
- 11 个文字样式覆盖 Hero、H1–H3、Title、Body、Label 与 Code。
- 3 个阴影样式覆盖 Subtle、Raised 与 Floating。

## 3. 原生组件

| 组件集 | 关键属性 |
|---|---|
| LogoMark | Tone |
| Button | Size × Style × State；可编辑 Label 与 Arrow |
| Chip | Tone；可编辑 Label 与 Dot |
| Composer | State × Value |
| Requirement Field | Empty / Filled / Confirmed / Conflict |
| Progress Step | Pending / Active / Complete / Error |
| Recommendation Card | Priority × Evidence；可编辑商品、价格与取舍 |
| Evidence Row | Collapsed / Expanded × Complete / Missing |
| Comparison Cell | Summary / Metric × Neutral / Best / Tradeoff |
| Metric Card | Neutral / Accent / Success |
| Feedback Panel | Loading / Empty / NoResults / Error |

组件实例保持与组件集连接；颜色使用 Variables 绑定，文字使用本地 Text Styles。Button 默认态连接 Hover 变体，Composer 默认态连接 Focus 变体，Evidence Row 支持展开与收起。

## 4. 交互路径

### Desktop 1440

欢迎 → 需求澄清 → 处理进度 → 推荐结果 → 方案对比 / 推荐依据。

- “查看示例方案”可直接进入推荐结果。
- 处理进度在 2.8 秒后进入推荐结果。
- 推荐卡可进入依据详情；“调整需求”返回澄清页。
- 对比页和依据页均提供返回路径。

### Mobile 390

欢迎 → 需求澄清 → 推荐结果 → 方案对比 / 推荐依据。

- 需求摘要折叠为单列卡片。
- 推荐结果使用单卡浏览，避免把桌面三列机械压缩。
- 对比页使用三列紧凑值矩阵；依据页把返回操作放在页头。
- 底部导航始终保留“导购 / 方案 / 项目”三个一级入口。

## 5. 状态覆盖

- 输入：空白、焦点、已填写、禁用、发送与停止。
- 需求：未填写、已填写、已确认、冲突、编辑。
- 处理：解析、检索、排序、整理依据、失败与重试。
- 结果：空内容、无满足条件候选、依据完整、依据缺失。
- 对比：0 个、1 个、3 个候选和上限状态。
- 安全：清除二次确认、网络错误保留上下文。
- 可访问性：可见焦点环、非颜色提示、至少 44 px 触控目标。

## 6. 公开演示边界

当前公开版实现规则式意图解析、结构化与关键词检索、Pointwise Logistic 排序和确定性中文模板。它不调用实时商品服务、外部数据库、商品 API 或在线 LLM，也不收集真实用户数据。

以下内容不能作为当前能力声称：实时价格、库存、销量、真实用户画像、线上 GMV / CVR、校准后的购买概率以及生产环境准确率。

所有商品、用户、查询、行为、评论和来源均为合成数据。缺少可靠证据时，界面会显示“依据不足”，并抑制对应结论。
