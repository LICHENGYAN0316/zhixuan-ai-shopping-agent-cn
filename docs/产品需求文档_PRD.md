# 智选 Agent 产品需求文档（PRD）

## 1. 产品定义

智选 Agent 是面向日化商品的中文智能选购原型。它将预算、品类、产品类型、肤质、关注功效、品牌偏好和明确避开成分整理为结构化需求，从 3,497 个离线历史商品中返回可比较的候选。

豆包只在服务端抽取需求字段。商品事实、当前品牌官方参考、过滤、排序和推荐理由均由本地数据与代码完成。商品对象的数值字段为 `price`，界面固定显示“样本价”。

## 2. 用户问题

1. 用户常用“敏感肌、想保湿、预算 200、不要香精”等自然语言表达需求。
2. 历史商品标题包含规格、活动噪声、功效词和成分词，不能直接当作已核实事实。
3. 当前品牌官方页面与历史商品可能属于不同市场或配方版本，需要在界面中保留边界。
4. 敏感肌、功效和成分避雷需要比普通名称/预算检索更严格的证据门槛。
5. 商品目录大而核实表覆盖很小，系统必须在没有证据时返回无候选或依据有限，而不是补写结论。

## 3. 当前目标与非目标

### 当前目标

- 解析 `category`、`productTypes`、预算区间、`skinType`、`sensitiveSkin`、功效、成分和品牌约束。
- 缺少预算上限时，复用现有澄清页追问并提供预算按钮。
- 按品类、产品类型、预算和品牌执行本地过滤。
- 对敏感肌、功效和成分避雷启用当前官方参考资格门槛。
- 返回最多三个候选，展示样本价、理由、取舍和证据来源。
- 保持欢迎、澄清、处理、推荐、对比、依据和项目说明的既有 UI 与交互。
- 通过清洗报告和发布数据契约测试证明目录字段与隐私边界。

### 非目标

- 不连接实时商品、库存、促销、购买链接、广告或交易 API。
- 不把历史销量/评论字段表述为当前销量或真实口碑。
- 不把 `merchant_claim_tags`、`title_ingredient_mentions` 或数值 `efficacy` 指数当作核实功效事实。
- 不把当前跨市场品牌参考反推为历史中国市场配方。
- 不提供监管备案、禁限用目录、浓度判断、医学诊断或治疗建议；当前数据中没有这些字段。
- 不上传商品目录、官方参考表或销售聚合给豆包。
- 不在仓库提交源 CSV、源工作簿、客户/订单记录或真实 API Key。

## 4. 实际用户旅程

现有状态集合与分支：

`欢迎 →（缺预算时进入预算澄清）→ 处理进度 → 推荐结果 → 方案对比 / 推荐依据 → 项目说明`

1. 用户输入“预算 200 元，敏感肌想保湿，避开香精”。
2. 浏览器向 `/api/intent` 发送当前需求文本。
3. 服务端强制豆包调用命名 Function，并校验完整参数；缺 Key、超时、上游失败或函数调用无效时返回本地解析结果。
4. `normalizeIntent` 把远端字段转成应用使用的 `Intent`。
5. 如果预算上限为空，系统进入既有预算澄清页；当前代码没有其他专门的澄清 UI。
6. 检索按品类、产品类型、预算区间、排除品牌和高级资格过滤。
7. 通过过滤的候选按需求词、功效匹配、品牌、样本价、官方参考状态和历史热度形成检索分，再与六个商品指数合成最终分数。
8. 返回 Top 3；用户可选择最多三个进行对比，或展开历史商品字段、需求映射和成分/功效证据。

## 5. 当前功能契约

| 编号 | 功能 | 实际验收 |
|---|---|---|
| F1 | 服务端需求解析 | `POST /api/intent` 接受 1–500 字需求；`Content-Length` 大于 4,096 字节时返回 413 |
| F2 | 豆包调用 | 使用 `ARK_API_KEY`、`ARK_MODEL`、受限 `ARK_BASE_URL`；`store:false`；强制调用 `extract_personal_care_intent` 并由服务端校验字段 |
| F3 | 降级 | 缺 Key、6 秒超时、上游非成功、缺函数调用或参数无效时返回 `provider=local-fallback` |
| F4 | 预算澄清 | 预算为空时返回一个预算问题；选择预算后自动继续 |
| F5 | 基础召回 | 品类、产品类型、`budgetMin`、预算上限和排除品牌执行硬过滤 |
| F6 | 敏感肌门槛 | `sensitiveSkin=true` 时只保留 `recommendation_eligibility.sensitive_skin=true` 的商品 |
| F7 | 功效门槛 | 需要核实证据且存在目标功效时，只保留 `efficacy=true` 的商品，并只在品牌声明与官方关注点中匹配 |
| F8 | 成分避雷 | 只对 `ingredient_avoidance=true` 商品判断；显式命中排除，官方明确“不含”放行，完整列表可用于未命中判断，关键成分列表的未知项不放行 |
| F9 | 可解释排序 | 最多召回 36 个，输出 Top 3；分数只用于排序，不是购买、功效或安全概率 |
| F10 | 证据页 | 展示历史商品字段、结构化需求、当前品牌官方参考或历史标题未核实状态 |
| F11 | 数据构建 | 两个 required 输入生成商品目录、质量报告、聚合、指标和 manifest |
| F12 | UI 保持 | DOM 主结构、CSS、响应式断点、导航、键盘提交、对比上限和证据展开行为不变 |

## 6. 豆包输出与应用 Intent

豆包 Function Calling 的字段为：

```json
{
  "category": "护肤",
  "productTypes": ["乳液"],
  "budgetMin": null,
  "budgetMax": 200,
  "skinType": "油性",
  "sensitiveSkin": true,
  "concerns": ["保湿"],
  "desiredEffects": ["保湿"],
  "avoidIngredients": ["fragrance"],
  "preferredIngredients": [],
  "avoidFragrance": true,
  "preferredBrands": [],
  "excludedBrands": [],
  "keywords": ["乳液", "保湿"],
  "needsClarification": false,
  "clarificationField": null,
  "confidence": 0.9
}
```

`normalizeIntent` 会将 `budgetMax` 转成应用字段 `budget`，规范品类和避开成分，生成 `preferredBrand`、`useCase`、`primaryPreference`、六维 `preferences` 与 `requiresVerifiedEvidence`。当前结构没有已知过敏史专用字段、质地偏好字段或 `medical_red_flag` 等医疗风险字段。

## 7. 检索与证据规则

### 普通检索

- `price`、`sales_count`、`review_count`、店铺和清洗标题来自离线历史快照。
- `price_label` 固定为“样本价”。
- 销量或评论缺失时保留 `null`；不按 0 处理。
- `merchant_claim_tags` 和 `title_ingredient_mentions` 由标题规则提取，只用于普通检索。
- 未触发核实证据需求时，历史热度可作为低权重排序信号。

### 当前品牌官方参考

- 当前只有 5 个商品有关联记录：4 个同名同规格当前跨市场参考，1 个当前系列参考。
- `evidence_level=official_current_reference` 表示存在人工整理的当前品牌页面，不表示历史配方已核实。
- 敏感肌资格来自当前品牌页相关声明；推荐理由固定说明它是跨市场参考。
- 功效匹配只搜索 `official_concerns` 和 `brand_claims`，输出保留“品牌官方”归属。
- 当前 `ingredients` 为字符串数组，没有监管或浓度字段。

### 成分避雷

- 用户必须用“避开、不要、不含、过敏、不能用”等明确表达，才会由本地规则提取避开项。
- 商品必须先具有 `ingredient_avoidance=true`。
- `normalized_ingredients` 显式命中避开项时排除。
- `normalized_formulated_without` 明确包含避开项时放行。
- `ingredient_list_completeness=full` 时，完整列表未命中可放行。
- `key_only` 记录若没有官方明确“不含”，其余成分保持未知并被排除。
- 当前规则支持有限同义词，例如香精、酒精/变性乙醇、paraben、矿物油、SLS/SLES、滑石粉、水杨酸和视黄醇。

## 8. 当前数据与指标

| 指标 | 当前值 | 含义 |
|---|---:|---|
| 去重商品 | 3,497 | 每个源商品 ID 的最新有效记录 |
| 店铺字段 | 22 | 快照中的店铺去重数 |
| 样本价完整率 | 100% | 无效或非正价格已排除 |
| 历史信号覆盖率 | 91.3926% | 至少有销量或评论字段 |
| 当前官方参考 | 5 | 人工整理并关联到商品的记录 |
| 敏感肌资格 | 3 | 当前品牌页含相关声明的记录 |
| 成分避雷资格 | 4 | 完整列表或官方“不含”信息足以支持有限判断 |
| 功效资格 | 4 | 当前品牌页声明可用于归属化展示的记录 |

这些数字描述目录和证据覆盖，不表示推荐准确率、产品安全率、功效成功率、购买概率或商业提升。

## 9. 风险与当前控制

| 风险 | 当前控制 |
|---|---|
| 历史字段被误读为实时行情 | `price_label` 固定“样本价”；不提供库存、促销或购买按钮 |
| 标题词被当作核实事实 | 独立保存为 `merchant_claim_tags` / `title_ingredient_mentions`；高级模式要求资格 |
| 当前参考被误读为历史配方 | 保存 `match_status`、`formula_market`、`formula_version_label`、核实日期和 notes；推荐理由明确不反推历史版本 |
| 关键成分列表被当作完整配方 | `ingredient_list_completeness=key_only`；未明确的避开项保持未知 |
| 豆包补写商品事实 | System Prompt 只允许需求抽取；商品数据不发送；推荐逻辑在本地 |
| API Key 泄露 | 仅服务端读取 `ARK_API_KEY`；`.env*` 被 Git 忽略 |
| 原始订单公开 | 只输出 `product_code` 级聚合，不输出客户编码、订单编码或地点 |
| UI 回归 | 继续使用同一状态枚举、组件和 CSS；当前尚无自动浏览器回归测试 |

## 10. 后续工作

- 扩大同市场、同规格、同版本的官方资料覆盖。
- 为服务端 `/api/intent` 增加自动化测试，包括长度、超时、重试和降级。
- 为关键桌面与移动状态增加浏览器回归测试。
- 如需监管、医学或浓度判断，必须新增相应权威数据结构与专门验证；当前版本不具备这些能力。
- 只有获得合法、脱敏、定义清晰的真实反馈标签后，才设计排序准确率评估。
