# 智选 Agent 产品需求文档（PRD）

## 1. 产品定义

智选 Agent 是面向 3C / 数码电商的中文智能导购原型。它不把“聊天”当作终点，而是帮助用户完成一个具体决策：从模糊需求出发，形成可解释、可比较、可行动的 Top-K 商品建议。

## 2. 用户问题

传统筛选器要求用户先理解 CPU、屏幕、续航等参数，搜索结果又容易被销量和广告排序影响。典型困难包括：

1. 用户只会表达“编程、轻度游戏、续航好”，不知道对应哪些参数。
2. 多个需求互相冲突，例如性能、轻薄、低价难以同时最大化。
3. 推荐结果缺少证据，用户无法判断为什么推荐、需要牺牲什么。
4. 对话答案与可购买候选脱节，容易出现不存在的参数或型号。

## 3. 目标与非目标

### 目标

- 将自然语言需求转为预算、品类、场景、偏好权重。
- 信息不足时主动提出一个高价值澄清问题。
- 召回满足硬约束的候选商品，并使用排序模型输出 Top-K。
- 每条建议引用商品库字段，说明推荐理由与主要取舍。
- 提供可复现的离线实验，验证排序模型优于简单基线。

### 非目标

- 不连接真实电商库存、价格、广告或交易系统。
- 不预测或宣称真实 GMV、CVR 提升。
- 不将合成评论当作真实消费者反馈。
- 不在当前版本中完成支付、售后或客服自动化。

## 4. 核心用户旅程

1. 用户输入“预算 7000 元，编程和轻度游戏，续航要好”。
2. Agent 提取：笔记本电脑、预算上限 7000、编程开发、续航优先。
3. 检索层按品类和预算召回最多 24 个候选，并保留描述、亮点、限制。
4. 排序层构造价格匹配、场景能力、偏好匹配、评分与销量等特征。
5. 模型输出相关概率并返回 Top 3。
6. 生成层解释价格余量、核心能力与评分证据，同时展示取舍提醒。
7. 用户切换候选，比较理由与限制。

若用户只说“推荐一台适合编程的电脑”，Agent 先询问预算上限，而不是直接给出泛化答案。

## 5. 功能需求

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F1 | 中文意图抽取 | 能识别 6 个品类、6 个使用场景、预算和主要偏好 |
| F2 | 主动澄清 | 无预算时输出明确预算问题，不生成商品结论 |
| F3 | 商品召回 | 仅从匹配品类与预算容差范围内返回候选 |
| F4 | 推荐排序 | 使用训练后模型参数计算分数，输出 Top 3 |
| F5 | 证据解释 | 每个结果至少展示价格、核心能力、评分和取舍 |
| F6 | 实验看板 | 展示模型、热门度基线、价格基线与指标定义 |
| F7 | 真实性声明 | 页面与文档清楚标注全部业务数据为合成数据 |

## 6. 成功指标

### 离线模型指标

- 主指标：NDCG@10。
- 辅助指标：Precision@5、Recall@10、MRR。
- 准入条件：NDCG@10 高于热门度基线，验证集与测试集差距不超过 3 个百分点。

### 产品指标（真实上线后）

- 主指标：导购会话到商品详情页的有效点击率、加购率。
- 体验指标：澄清完成率、推荐理由展开率、会话后满意度。
- 护栏指标：无证据参数率、超预算推荐率、响应时延、单会话模型成本、投诉率。

## 7. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 商品幻觉 | 生成层只能使用召回商品字段；展示商品 ID 与证据文本 |
| 位置偏差 | 训练特征不使用曝光位置；真实业务需 IPS/随机桶校正 |
| 合成数据过于理想 | 同时报告基线和限制，不外推线上收益 |
| 用户需求冲突 | 明确展示取舍，不用单一“最优”掩盖约束 |
| 冷启动 | 使用内容属性和场景匹配，后续再融合协同信号 |

## 8. 迭代路线

- V1（当前）：合成数据库、结构化检索、pointwise 排序、模板生成、离线指标。
- V2：中文 embedding 召回、LambdaMART、对话上下文与多轮偏好更新。
- V3：在线 LLM、引用校验、A/B Test、GMV/CVR/满意度联合优化。
